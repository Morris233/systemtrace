# SystemTrace — 产品与开发需求规格（PRD）

- 文档版本：1.0（2026-10-26）
- 产品代号：SystemTrace
- 首发版本：v0.1.0
- 系统：Windows 11 x64（Windows 10 不作为首版验收目标）
- 语言：简体中文、English；UI 默认跟随操作系统显示语言，无法匹配则英文；可手动切换
- 开源许可证：MIT（提交前核查所有第三方组件许可证）
- 开发路线：C# / .NET 10 / WPF / MVVM / SQLite；本地优先、默认非管理员权限、只读监测

## 1. 定位与用户故事

**一句话定位**：Know what changed before something broke.（在问题出现之前，知道系统发生过什么变化。）

SystemTrace 是一款通过间歇式系统快照和可靠差异计算，记录 Windows 软件、启动项、设备驱动、网络适配器变化的桌面应用。它不是杀毒软件、系统清理器、完整审计工具或自动诊断系统。发现变化 ≠ 证明变化造成故障。

- US-01：作为用户，我第一次启动时能建立基线，并清楚得知首次扫描不会被误认为新增了整个系统。
- US-02：我安装、卸载或更新软件后，能在下次扫描发现变化并查看证据。
- US-03：我修改某个启动项后，能对比前后命令和来源位置。
- US-04：网络或驱动出故障时，我能查看问题发生之前的可疑变化及其时间窗口。
- US-05：我能关闭后台监测、退出托盘应用、清理历史和导出经过隐私处理的报告。
- US-06：我能用中文或英文完整使用软件与阅读文档。

## 2. 范围与非目标

### P0（v0.1 必须实现）

1. 手动扫描；首次完整基线；默认仅在用户主动打开主程序后开始扫描。
2. 可选系统登录时启动；可选关闭窗口时最小化到托盘；可选托盘定时扫描。默认自动启动关，托盘后台运行关；定时扫描默认 30 分钟，仅在启用后台监测的运行期生效。
3. 四种采集器：已安装软件、Run 注册表与启动文件夹启动项、PnP 驱动属性、网络适配器。
4. 每个采集器独立状态：Succeeded / Partial / Failed / Skipped，区分无法读取、空结果与对象缺失。
5. 以稳定键与规范化属性比较差异；新增/移除/修改；快照持久化、避免重复事件。
6. 首页概览、变化时间线、变化详情、快照比较、故障时间回溯、设置；全文搜索和类别筛选。
7. 本地 SQLite、数据库迁移、事务提交、基本日志、时间戳和数据保留设置。
8. JSON/CSV 报告导出（手动触发）及路径/命令/个人信息的遮盖选项。
9. 中文/英文 UI 和 README；深浅色主题、键盘导航、无障碍控件名称。
10. GitHub Actions Windows 构建与单测、Release ZIP（win-x64）、MIT、隐私说明。

### P1（v0.2）

Windows Update 历史、Windows Event Log 事件辅助、任务计划程序启动项、微软商店应用更全面的支持、Windows 通知细化、数据归档压缩。

### 排除（v0.1 不允许实现）

自动修复、自动修改驱动/注册表、远程上报、AI 推断原因、完整文件系统监控、全盘扫描、修改用户启动项、采集浏览历史、系统级服务安装、全机其他用户的个人软件清单。

## 3. 关键工作流

1. **首次运行**：语言/隐私提示 → 手动建立基线 → 展示扫描范围与结果 → 无 Changes 事件。
2. **再次扫描**：点击 Scan now → 显示各采集器进度 → 先持久化扫描结果及有效数据 → 比较各类别最近一次有效基线 → 事务内保存变化与推进基线 → 刷新时间线。
3. **故障回溯**：输入首次发现故障的时间及可选关键词/类别 → 检索此前 24 小时（可调整为 1h/6h/24h/7d）变化 → 排序仅参考时间接近、类别关联、数据完整性 → 显示“排查线索，并非确定原因”。
4. **托盘运行**：用户主动启用并允许关闭窗口最小化到托盘 → 菜单包含打开、立即扫描、暂停监测、退出 → 退出必须释放资源；无偷偷重启。
5. **登录启动**：单独设置开关，清晰告知可在系统设置中撤销；使用当前用户 Run 项，仅管理软件自身键，关闭时只移除由自身创建且值匹配的键。

## 4. 采集器规范

参见 [ARCHITECTURE.md](ARCHITECTURE.md) 和 [DATA-MODEL.md](DATA-MODEL.md)。

### SoftwareCollector
- 只读枚举 HKCU 和 HKLM 的 `Software\Microsoft\Windows\CurrentVersion\Uninstall`，HKLM 同时读取 32/64 位注册表视图；对 HKCU 视系统 API/视图行为显式测试；**禁止基于 Wow6432Node 字符串硬编码而导致双计数**。
- 字段：RegistryHive、RegistryView、SubkeyName、DisplayName、DisplayVersion、Publisher、InstallLocation（敏感）、UninstallString（敏感，仅在必要时读取，不默认保存）；可选 InstallDate 不用于变化实际发生时间。
- 稳定键优先使用规范化的 registry hive/view/subkey 全路径；内容不相同但同名软件不能粗暴合并。
- 缺失 DisplayName 的系统条目可以跳过但应在扫描摘要计数；包含 SystemComponent 的条目可在 UI 过滤而非暗中删除。
- **限制**：不能覆盖全部便携应用、全部 Store 应用和其他用户的每个安装项。

### StartupCollector
- 当前用户与系统 Run/RunOnce：HKCU/HKLM 的 `Software\Microsoft\Windows\CurrentVersion\Run`、`RunOnce`（按可读取权限）；HKLM 32/64 视图；当前用户与公共 Startup 文件夹（用 Environment.SpecialFolder 等系统 API 定位）。
- RunOnce 是一次性项，变化须提示可能短暂；不读取其他用户配置单元。
- 字段：来源类别、完整源键、值名、命令文本（个人信息敏感）、文件路径、修改信号（文件夹项可读取文件修改时间，但不可用作确切事件时间）。
- 稳定键包含 source scope、view 与注册表值名/相对文件路径；禁止执行采集到的命令。
- **限制**：任务计划程序、服务、启动批准状态、其他自动启动机制留至 P1；UI 使用“已监测启动来源”而非“所有启动项”。

### DriverCollector
- 通过 Windows Configuration Manager / SetupAPI 读取当前 PnP 设备，取 Device Instance ID（稳定键）、FriendlyName、Class、Manufacturer、DriverProvider、`DEVPKEY_Device_DriverVersion`、可能的驱动日期。
- 设备暂时消失或枚举失败需与真正移除区分；默认只显示 present devices，非 present 设备的差异显示应谨慎标记为“本次未检测到”，不是断言卸载。
- 关键属性不可用时保留 null 与字段级错误，不用空字符串代替；避免高开销 WMI 多次重复查询。

### NetworkCollector
- `NetworkInterface.GetAllNetworkInterfaces()` 获取网卡标识、名称、接口类型、OperationalStatus、描述；需要补充启用/禁用状态时使用受支持的 Windows API 或 CIM，明确字段来源与无法读取状态。
- 稳定键用网卡接口 GUID/ID，不能用显示名称；不采集 SSID、Wi-Fi 密码、IP、MAC 等识别信息到历史记录（首版默认），网络变化聚焦接口增加/减少/状态/描述。
- 与驱动采集可能出现交叉事件，UI 可以相关联但数据库保留不同类别的原始证据。

## 5. 用户体验及质量要求

- 首次启动有扫描说明；显著标识最后**成功完整**扫描时间与最后**尝试**扫描时间。
- 没有数据时展示友好空状态与“建立基线”；没有变化时显示“自上次成功扫描以来未发现变化”。
- 扫描显示非阻塞进度；同一时刻仅允许一个扫描流水线；取消后应正确处理未提交结果。
- 时间展示本地时间、存储 UTC ISO 8601，事件必须有 `observed_from_utc`/`observed_to_utc` 扫描窗口。
- 数据库与日志保存在 `%LOCALAPPDATA%\SystemTrace\`，避免管理员权限；不可将个人日志提交 Git。
- 默认不联网、不包含遥测与崩溃自动上传。
- 预期体验目标（非事实承诺）：主窗口交互保持响应；四模块扫描目标普通电脑 < 30s；首次启动冷启动目标 < 3s。以基准测试评估，不达标时记录原因而非伪造数字。
- 标准 DPI 100%–200% 下文字不裁切；最低窗口尺寸 960×620；触控非首要目标。
